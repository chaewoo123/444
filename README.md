# 용도지역 개선안 대시보드

**사이트 열기 → https://444-git-zoning-solution-hi-021f.vercel.app**

지역을 입력하면 현재 용도지역을 위성지도에 겹쳐 보여 주고, 솔루션 탭에서 대안 A·B·C를 세 가지 기법(사회적 비용-편익, 계획 대차대조표, 목표-성취)으로 비교한다.

이 브랜치(`zoning-solution`)는 `main`·`develop`과 이력이 이어지지 않은 별도 프로젝트다. 고칠 때는 이 브랜치에 올린다.

## 인증키

브이월드 인증키는 저장소에 없다. 저장소가 공개라서 키를 올리면 누구나 본다.

| 환경변수 | 내용 |
|---|---|
| `VWORLD_KEY` | 브이월드 오픈API 인증키 |
| `VWORLD_DOMAIN` | 키 발급 때 등록한 서비스 URL. 없으면 `INCORRECT_KEY` 오류가 난다 |

- **PC에서 실행할 때**: 팀장에게 받은 `.env` 파일을 `dashboard_server.js` 옆에 넣는다. `.gitignore`가 올라가지 않게 막아 둔다.
- **Vercel에 배포할 때**: 프로젝트 설정의 Environment Variables에 위 두 값을 넣는다.

## PC에서 실행

Node 18 이상.

```bash
git clone -b zoning-solution https://github.com/chaewoo123/444.git zoning-solution
cd zoning-solution
node dashboard_server.js
```

브라우저에서 http://localhost:5180 을 연다.

## Vercel 배포

`index.html`은 정적 파일로, `api/zoning.js`는 서버 함수로 올라간다. 화면은 모든 요청을 `/api/zoning?r=<기능>`으로 보낸다. 환경변수 두 개가 들어 있어야 검색과 지도가 동작한다.

## 경사 자료 (DEM)

경사는 국토지리정보원 공개DEM 90m 도엽으로 계산한다. 도엽은 저장소에 없다. 원본 DEM은 국외 반출 제한이 있어 저장소나 외부 서비스에 올리지 않는다.

국토정보플랫폼(자료실 → 지도자료 → 카탈로그 → 공개DEM)에서 받아 아래처럼 둔다.

```
dem_ngii/36701/36701.img
```

도엽이 없으면 솔루션 탭에 필요한 도엽 번호가 나온다. Vercel 배포본에는 도엽이 없으므로 솔루션 탭의 경사·대안 계산은 PC에서만 된다.

## 자료 출처

| 내용 | 출처 |
|---|---|
| 지역 검색, 위성지도, 용도지역, 행정경계, 개별공시지가 | 브이월드 검색 API 2.0 · WMTS · 2D 데이터 API 2.0 |
| 경사 | 국토지리정보원 공개DEM 90m |
| 인구 | 인구총조사 2024 (SGIS) — `main` 브랜치의 `api/sgis.js` 배포본을 부른다 |

## 계산 규칙

- 대안 A 보전 우선: 현재 주거·상업·공업 중 경사 25% 초과 → 녹지
- 대안 B 개발 우선: 현재 비시가화 중 경사 25% 이하 → 개발 후보
- 대안 C 절충: 현재 비시가화 중 경사 15% 이하 → 개발 후보
- 개발 후보 중 경사 5% 이하는 "공업 가능"으로 따로 표시한다. 후보를 주거·상업·공업으로 나누는 수요 자료는 없어서 나누지 않는다.
- 목표-성취: 지표 값(%)을 20%p 구간으로 1~5점 환산, 가중치는 화면에서 입력(합 1.00)
- 비용-편익: 편익 = 전환 면적 × (전환 후 − 전환 전 평균 공시지가). 비용 자료가 없어 순편익·편익비용비는 공란. 읍면동에서만 계산
